# 🌐 The Digital Sovereignty Stack
### A-Z Guide: Private VPN, Network-Wide Ad-Blocking, and Global Exit Nodes
This repository contains the blueprint for a high-performance, self-hosted networking stack. It is designed to maintain privacy, block advertisements, and ensure internet access even under the most restrictive network conditions.
## 🏗️ System Architecture
 * **The Server:** A low-power Always-On device (Raspberry Pi, Mini PC, or NUC) located at **Home Base (Location A)**.
 * **Primary Tunnel:** **WireGuard** for high-speed, encrypted entry to your network.
 * **The Bouncer:** **Pi-hole** acting as a network-wide filter for ads and trackers.
 * **The Shield:** **Mullvad VPN** as a global exit node for anonymity and P2P protection.
 * **The Emergency Exit:** **MasterDnsVPN** (DNS Tunneling) for bypassing strict firewalls and DPI.
## 🛠️ Phase 1: Server Setup (Location A)
### 1. Prerequisite: Docker & Compose
Using Docker ensures your setup is modular and easy to migrate.
```bash
sudo apt update && sudo apt upgrade -y
sudo apt install docker.io docker-compose -y

```
### 2. Deployment
Create a docker-compose.yml file to launch the core stack:
```yaml
version: "3"
services:
  # DNS Filtering (Ad-Blocking)
  pihole:
    image: pihole/pihole:latest
    container_name: pihole
    ports:
      - "53:53/tcp"
      - "53:53/udp"
    environment:
      - TZ=UTC
      - WEBPASSWORD=SetYourAdminPassword
    restart: unless-stopped

  # Primary VPN Access
  wireguard:
    image: linuxserver/wireguard:latest
    container_name: wireguard
    cap_add:
      - NET_ADMIN
    environment:
      - SERVERURL=your.ddns.address
      - PEERDNS=172.17.0.1 # Routes through Pi-hole
    ports:
      - "51820:51820/udp"
    restart: unless-stopped

  # Emergency DNS Tunnel (MasterDnsVPN)
  # Uses MIT Licensed core for harsh network environments
  masterdnsvpn:
    image: masterking32/masterdnsvpn:latest
    container_name: dns_tunnel
    ports:
      - "5353:53/udp" # Map to an alternate port if Pi-hole is on 53
    volumes:
      - './masterdns:/config'
    restart: unless-stopped

```
## 🆘 Phase 2: Emergency Backup (MasterDnsVPN)
When standard VPN protocols (Wireguard/OpenVPN) are blocked by deep packet inspection (DPI) in hotels or restrictive regions, use the **DNS Tunneling** bridge.
### 1. How it works
This component disguises your data as standard DNS queries. It is significantly slower than Wireguard but nearly impossible to block without shutting down the entire network's DNS system.
### 2. Configuration
 1. **Server Side:** Set up an NS Record at your domain provider pointing a subdomain (e.g., v.yourdomain.com) to your Home Base IP.
 2. **Client Side:** Run the MasterDnsVPN client on your laptop/mobile. Point it to your delegated subdomain.
 3. **Proxy:** Connect your browser to the local SOCKS5 proxy generated by the client (default: 127.0.0.1:18000).
## 🛡️ Phase 3: Privacy & Anonymity Layer
To ensure your Home Base IP is not exposed during sensitive activities:
 1. **Mullvad Integration:** Configure the server to route outbound traffic through Mullvad.
 2. **Interface Binding:** Bind applications (like qBittorrent) to the VPN interface (tun0) to ensure an immediate "Kill Switch" if the tunnel drops.
## ✈️ Phase 4: Mobility & Global Access
### 1. Handling Dynamic IPs (DDNS)
Use a DDNS provider (e.g., DuckDNS) to ensure your mobile devices can always find your server, even if your ISP changes your home IP address.
### 2. The Traveler Setup (Location B)
For the best experience, use a travel router (e.g., **GL.iNet Beryl 7**).
 * **At Home:** Beryl 7 connects to Location A via Wireguard.
 * **On the Go:** All your devices connect to the Beryl 7 Wi-Fi. If Wireguard is blocked, switch the Beryl 7's "Exit Node" to use the MasterDnsVPN bridge.
